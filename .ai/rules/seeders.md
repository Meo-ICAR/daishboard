# Seeders

## MediatoreDashboardSeeder: cruscotti dominio proforma
MediatoreDashboardSeeder crea 3 dashboard (database='proforma', categorie Produzione/Contabilita) con 13 widget master + 3 figli di drill-down, dalla raccolta query operative del mediatore creditizio. È idempotente (esce se esiste già la dashboard "Pipeline & SLA Pratiche") e registrato in DatabaseSeeder dopo DashboardWidgetSeeder. Usa DB::table()->insert() (bypassa StampsOwnership → company_id/user_id restano NULL = globali). type canonici: table/bar/line/pie (chiavi App\Support\ChartType, non "Pie Chart"). I 3 widget figli mantengono i parametri :id_pratica / :denominazione_banca / :competenza+:trimestre e sono legati via master_widget_id + master_filter_column (colonna presente nell'output del master): NB il runtime NON sostituisce ancora i :param (né WidgetDatasetRunner né SharedWidgetController), quindi da soli danno errore PDO — funzionano solo come target di drill-down e sono forward-compatible. SQL verificato contro proforma prima del seeding.

## MediatoreDashboardSeeder: cruscotti dominio proforma
MediatoreDashboardSeeder crea cruscotti per il database 'proforma'. Idempotenza PER SINGOLA dashboard (skip se esiste già stessa title+database+company_id). Registrato in DatabaseSeeder dopo CompanySeeder (serve companies.id=2) e DashboardWidgetSeeder. Usa DB::table()->insert() (bypassa StampsOwnership). type canonici table/bar/line/pie (chiavi App\Support\ChartType). Contenuto: (a) 3 dashboard "di dominio" con company_id NULL (Pipeline & SLA Pratiche, Provvigioni & Redditività, ENASARCO & Disallineamenti OAM) = 13 master + 3 figli, SQL verificato contro proforma; (b) dashboard "Gestione Provvigioni & Fatturazione" con company_id=2 = 16 master + 3 figli, RETTIFICA dei widget storici company_id=1: type canonicizzati, colonna inesistente invoices.fornitori_id sostituita (join fornitoris su fornitore_piva, filtro clienti_id IS NULL/NOT NULL per passive/attive), virgola mancante corretta, parametri posizionali ? -> figli di drill-down con :named. Scartati i widget su tabelle assenti in proforma: calls/calls_esitos/leads/proforma_provvigione/vwprovv2cogedetail (e la dashboard "Report Chiamate & Lead"). NB: il company aibackground di CompanySeeder cita fornitori_id su invoices/provvigioni ma nel DB reale proforma NON esiste. I :param non sono ancora sostituiti a runtime (vale sia per i figli qui sia per la sezione 5 di config/data_navigator.php).

## HivDashboardSeeder: cruscotti clinici company 3
HivDashboardSeeder crea 3 dashboard company_id=3, database='hassisdadmin', categoria 'Clinica': "Rischio Cardiovascolare & Placca Carotidea" (5 master + 8 figli), "Demografia Pazienti & Trattamenti" (10 master), "Gestione Pazienti" (4 master) = 19+8 widget. Rettifica dei widget storici company_id=3: type canonicalizzati (Pie Chart->pie...), type portati a 'table' dove la query non ha colonna categoria o è un cross-tab multidimensionale (Sede/morfologia placca, Fattori di rischio tradizionali), titoli grezzi (erano il prompt) ripuliti, `iniziali`->`pazientecode` (regola privacy profilo hiv), `active=1` aggiunto dove mancante su patients/patient_visits (non sulle query su viste vw*), master_filter_column valorizzato sui figli 54-61 (erano NULL) con una colonna reale del master. I figli NON hanno :param (sono sotto-analisi pre-filtrate: il runtime esegue la loro query verbatim). Idempotenza per dashboard (title+database+company_id). Registrato in DatabaseSeeder dopo CompanySeeder (serve companies.id=3) e MediatoreDashboardSeeder. SQL verificato contro hassisdadmin. Vedi anche la voce MediatoreDashboardSeeder per lo stesso pattern.
