# Seeders

## MediatoreDashboardSeeder: cruscotti dominio proforma (SYNC)
Il seeder NON è più "idempotente per skip": è una SINCRONIZZAZIONE. `run()` per ogni gruppo del `blueprint()`: get-or-create della dashboard (chiave title+database+company_id), poi `syncWidget()` upsert di ogni widget (chiave dashboard_id+title+ruolo master/figlio) e DELETE dei widget della dashboard non più nel blueprint (solo quelli senza chat_history_id). Quindi rilanciando `php artisan db:seed --class=MediatoreDashboardSeeder` si applicano in place le correzioni di query/type e si rimuovono i widget obsoleti — è così che si "correggono le query in dashboard_widgets". Tocca SOLO le sue 4 dashboard: "Pipeline & SLA Pratiche" (9 master), "Provvigioni & Redditività" (7 master + 2 figli), "ENASARCO & Disallineamenti OAM" (6 master + 1 figlio) — tutte company_id NULL — e "Gestione Provvigioni & Fatturazione" company_id=2 (10 master + 3 figli). Non tocca la storica id 3/4 company_id=1. type canonici table/bar/line/pie. Query costruite sul modello dati REALE di proforma (pratiches/provvigioni/venasarcotrimestre/pratiches_statos/provvigioni_statos + vista vwenasarcotot); usa `provvigioni.istituto_finanziario` per raggruppare per banca senza JOIN, `provvigioni.importo` (mai importo_effettivo), scadenziario ENASARCO con `competenza = YEAR(CURDATE())` (non più il 2026 hardcoded). La dashboard company_id=2 non usa più `invoices` (quasi vuota in proforma) ma `provvigioni`. I 6 widget figli hanno :param (:id_pratica/:denominazione_banca/:competenza+:trimestre/:denominazione_riferimento/:tipo_prodotto): drill-only, non sostituiti a runtime. Il test MediatoreDashboardSeederTest conta i widget dal blueprint via reflection (niente numeri hardcoded).

## HivDashboardSeeder: cruscotti clinici company 3
HivDashboardSeeder crea 3 dashboard company_id=3, database='hassisdadmin', categoria 'Clinica': "Rischio Cardiovascolare & Placca Carotidea" (5 master + 8 figli), "Demografia Pazienti & Trattamenti" (10 master), "Gestione Pazienti" (4 master) = 19+8 widget. Rettifica dei widget storici company_id=3: type canonicalizzati (Pie Chart->pie...), type portati a 'table' dove la query non ha colonna categoria o è un cross-tab multidimensionale (Sede/morfologia placca, Fattori di rischio tradizionali), titoli grezzi (erano il prompt) ripuliti, `iniziali`->`pazientecode` (regola privacy profilo hiv), `active=1` aggiunto dove mancante su patients/patient_visits (non sulle query su viste vw*), master_filter_column valorizzato sui figli 54-61 (erano NULL) con una colonna reale del master. I figli NON hanno :param (sono sotto-analisi pre-filtrate: il runtime esegue la loro query verbatim). Idempotenza per dashboard (title+database+company_id). Registrato in DatabaseSeeder dopo CompanySeeder (serve companies.id=3) e MediatoreDashboardSeeder. SQL verificato contro hassisdadmin. Vedi anche la voce MediatoreDashboardSeeder per lo stesso pattern.
